# Feature Specification: 内容质量循环(主链路全链质量兜底)

**Created**: 2026-06-12
**Status**: Draft
**Input**: 用户描述:"已有黄金样张作为目标标准,对抓取链路生产的内容进行质量评估和质量兜底,保证生产的内容都符合样张标准;不需要用户一次次用提示词反馈质量问题——目标已定,AI 给 AI 自己提示词、自己执行、自己循环达成目标。范围覆盖从抓取内容到最终入库升格的全链。"

## Clarifications

### Session 2026-06-12

- Q: 主链路处理节奏(日批/小时增量/连续)? → A: **24 小时连续运行**(常驻流水线,队列有活即处理,不设每日窗口);部署在 Mac mini(非本机);唯一硬约束是与 AI TRENDS 现役三条链路(定时占位 05:30/07:30/08:00/10:00)无性能/资源冲突——保障方式不是错峰窗口,而是**资源天花板**:串行单工(同一时刻只处理一篇)、LLM 全走远程 API(本地仅网络与文件 IO)、源轮询限频;外层常驻循环属宪法原则 1 允许的"等外部触发"最外层,须可中断退出
- Q: 修复能力如何对其他 6 个循环"通用"? → A: **内核+适配卡模式**:通用内核只懂协议不懂业务(签名 schema/生命周期状态机/升级规则/S-B-R 权限/watchdog/案例库);每循环自带修复适配卡注册,缺卡不许上线;契约先行(本 feature 交付 schema+格式 spec+第一张卡)、行为引擎后置(Plan 4,待 3+ 张真实卡检验契约);新循环设计纪律=八要素卡+修复适配卡
- Q: 极端涌入/成本失控如何防(日级总预算闸?) → A: **不设吞吐限额,机制优先解决**:①源站改版类 → Scrapling 自适应抓取(已锁工具栈)+ 归档段锚点校验兜底;②异常涌入类 → 单源单日产量超中位数倍数阈值时整批进隔离区待查(不进处理队列)+ 内容 hash 幂等去重 + 既有 per-source 限频;③bug 跑飞类 → 宪法原则 1 的有界常量(单篇修复≤3 轮)+ **串行单工即天然节流阀**(队列爆只增加排队深度,不增加烧钱速率)+ watchdog 兜底。入库量与吞吐均不设限,质量与机制定多少

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 合格内容无人值守入库 (Priority: P1)

知识库主人提供(或源配置自动发现)一条内容 URL。系统自动完成抓取、原文归档、价值准入、知识提炼、质量评估、修复收敛、门控、升格入库、图谱回链的全部环节,产出一篇达到黄金样张质量级别的知识页。全程没有任何人工提示词、确认或质量反馈介入。

**Why this priority**: 这是整个知识库 2.0 的生产主动脉;没有它,知识进库依赖人肉操作,7×24 第二大脑不成立。

**Independent Test**: 投入一条已知优质内容 URL(如黄金样张原文),等待管线完成,验证产出页通过 14 步清单全部标准,且过程日志中无人工介入点。

**Acceptance Scenarios**:

1. **Given** 一条领域内优质长文 URL 已入待处理队列, **When** 管线心跳触发处理, **Then** 产出的知识页通过全部结构检查、质量量规、门控与收尾完整性检查,自动升格入库并完成索引与图谱回链
2. **Given** 黄金样张的原始 URL, **When** 管线端到端重跑, **Then** 产出与黄金样张结构等价(14 步清单逐项 pass)
3. **Given** 管线处理完成一篇内容, **When** 查看处理记录, **Then** 该篇的每个环节判定、修复轮次、消耗预算完整可追溯

### User Story 2 - 不合格内容被正确拒收 (Priority: P1)

低价值内容(洗稿、新闻简报、跑题内容)进入管线后,在消耗昂贵提炼资源**之前**被准入环节拒收,拒收原因记录在案。知识库不因"今天没产出"而降低标准。

**Why this priority**: "知识在于精不在于泛"——质量级别由"放进什么"与"拒掉什么"共同定义;拒收失效则知识库坟场化,且提炼成本失控。

**Independent Test**: 投入两个已知负样本(洗稿型 X Article、新闻型视频简报),验证两者均被拒于准入环节,拒收原因可读,且未产生提炼消耗。

**Acceptance Scenarios**:

1. **Given** 洗稿型内容(对已有知识无新增量)入队, **When** 准入判定执行, **Then** 内容被拒收,原因标注"新颖度不足",未触发提炼环节
2. **Given** 新闻型内容(无可执行 how)入队, **When** 准入判定执行, **Then** 内容被拒收,原因标注"How 倾向不足",未触发提炼环节
3. **Given** 一篇内容提炼后修复 3 轮仍未达质量标准, **When** 修复上限触达, **Then** 内容留在候选区不入库,失败原因与轮次记录在案

### User Story 3 - 质量缺陷由系统自我修复 (Priority: P1)

提炼产出存在质量缺陷(如某步骤缺少完成判定、某论断无出处锚点)时,系统将缺陷定位到具体位置、自动生成修复指令、定点重写、再次评估——这个反馈环完全在机器内部闭合,知识库主人不参与。

**Why this priority**: 这是"AI 给 AI 提示词"的核心兑现;若质量反馈仍需人写提示词,loop 工程的解放价值归零。

**Independent Test**: 构造一篇含已知缺陷的提炼稿,验证系统输出的缺陷清单定位准确、修复后该缺陷消除且其余部分未被改动。

**Acceptance Scenarios**:

1. **Given** 提炼稿某论断缺出处锚点, **When** 质量评估执行, **Then** 缺陷清单点名该论断及所在小节,修复后锚点补全且其他小节内容不变
2. **Given** 同一质量维度在近期多篇内容上反复不达标, **When** 聚集阈值触达, **Then** 系统自动发起管线级校准(修正的是生产环节配置,而非逐篇修补),校准后用全量语料重验

### User Story 4 - 质量标准不随时间漂移 (Priority: P2)

管线长期运行中(模型更新、源变质),知识库主人不需要主动发现质量下滑——系统定期抽检已入库内容,达标率跌破阈值时自动触发再校准,并在周报中可见。

**Why this priority**: 防止"上线时达标、三个月后劣化"的静默腐化;但首月内无历史积累,优先级低于前三者。

**Independent Test**: 模拟一批低于标准的入库内容进入抽检窗口,验证再校准被自动触发且事件可见。

**Acceptance Scenarios**:

1. **Given** 周抽检样本达标率低于阈值, **When** 抽检任务完成, **Then** 校准任务自动创建,周报含该事件及原因摘要

### Edge Cases

- 抓取失败(付费墙/反爬/超时)→ 显式记录跳过,不静默,不阻塞批次内其他内容
- 原文与归档锚点对不上(原文改版)→ 锚点校验失败,该篇终止于归档环节
- 质量评估服务不可用 → 切换备用裁决方(异族约束仍满足);两者皆不可用 → 该篇挂起,不降级放行
- 升格依赖的知识库内容标准修订(取消逐条人批)未生效前 → 管线运行至门控通过为止,升格环节保持提议状态不写库(fail-closed 兜底)
- 与已有知识页高度相似但携带新 how → 不拒收,按增量喂养路径处理(并入既有页,见星级体系混层规则)
- 同一 URL 重复入队 → 幂等去重(内容指纹),不重复消耗
- 单源单日产量超常(如源站改版误判、聚合页爆量)→ 该源当批整体进隔离区待查,不进处理队列,事件可见
- 单篇预算(轮次/时间/调用额度)耗尽 → 终止并显式记录,部分完成不得报成功

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 将内容处理组织为七个顺序环节(抓取 → 原文归档 → 准入 → 提炼组装 → 质量门控 → 升格 → 收尾),任一环节检查不过,后续环节 MUST NOT 启动
- **FR-002**: System MUST 在抓取环节产出全文与来源元数据(标题/作者/发布日期/URL),抓取失败 MUST 显式记录
- **FR-003**: System MUST 将原文以带引用锚点的归档形式保存,归档保持原文语言不翻译;锚点完整性 MUST 被校验
- **FR-004**: System MUST 在提炼发生前执行准入硬判定(主题相关性、可执行知识倾向、对既有知识的新颖度),三项均为通过/不通过二值判定,无连续分数排序
- **FR-005**: System MUST 按量规三层评估提炼产出:结构层(确定性检查,先行)、内容质量层(十个维度:论断锚定、How 密度、How 可执行性、证据诚实、解读分离、摘要密度、新颖增量、图谱边强度匹配、未来问题质量、适用边界)、链级(门控+收尾完整性);层间顺序 MUST 为成本递增(免费检查先于付费评估)
- **FR-006**: 质量评估输出 MUST 是定位到具体小节的缺陷清单(维度+位置+缺陷描述),MUST NOT 是无定位的分数
- **FR-007**: System MUST 基于缺陷清单自动生成修复指令并定点重写被点名部分,未点名部分 MUST NOT 被改动;修复-再评循环 MUST 有界(上限为具名常量),触限未收敛 MUST 留候选区不入库
- **FR-008**: 内容生产与质量裁决 MUST 由不同模型家族执行;质量评估服务不可用时 MUST 有异族备用方;全部不可用时 MUST 挂起而非降级放行
- **FR-009**: 通过全部五道门(门控硬检查全过、判定置信度高、图谱就绪、规范检查零问题、独立复核通过)的内容 MUST 自动升格入库,无人工逐条审批;前置依赖:知识库内容标准的对应修订生效,生效前升格环节 MUST 停在提议状态
- **FR-010**: 升格 MUST 附带收尾完整性:索引行为一句人读摘要、被引概念页双向回链、全部触及文件规范检查通过
- **FR-011**: System MUST 为每篇内容记录全生命线账本(各环节判定、修复轮次、耗时、资源消耗),格式遵循全循环统一约定
- **FR-012**: System MUST 支持端到端校准:以固定语料集(含已知正样本与负样本)全量重跑并出统计报告;管线配置变更 MUST 经语料重验后才转正
- **FR-013**: System MUST 周期抽检近期入库内容,达标率跌破阈值 MUST 自动触发校准任务并在周报可见
- **FR-014**: 量规与各环节判定标准 MUST 以版本化文档形式外置(技能包),变更可追溯;量规语义变更属红线,需知识库主人确认
- **FR-015**: 自动入库的前 50 条 MUST 保留升格前快照,支持抽查与一键回滚
- **FR-016**: 全链所有判定与修复 MUST 在机器内部闭环,正常运行(非红线变更、非故障升级)不得要求知识库主人提供提示词、确认或质量反馈
- **FR-017**: System MUST 以机制而非吞吐限额防御极端输入:内容指纹幂等去重;单源产量异常(超中位数倍数阈值)时该批整体隔离待查;处理 MUST 串行单工(同一时刻仅一篇消耗提炼/复核资源),使排队深度增长不放大资源消耗速率
- **FR-018**: 本循环 MUST 随交付提供修复适配卡(故障签名表、各签名诊断线索、静默动作白名单、可自动修复范围、红线保护路径、修后验证方法、回滚方法、健康监测配置),作为全循环通用修复框架的第一张注册卡;全部故障事件 MUST 以统一签名格式落故障账本;同一签名第 3 次出现 MUST 升级至知识库主人可见的简报

### Key Entities

- **原文归档(raw)**: 抓取的原始内容 + 来源元数据 + 引用锚点体系;一篇知识页的证据底座
- **知识页候选(candidate)**: 提炼产出的结构化知识页,处于候选区,含全部模板章节与图谱边声明
- **知识页(active)**: 通过五道门后入库的正式知识页,可被检索与引用
- **量规(rubric)**: 版本化的质量标准全集(结构层 + 内容质量层 + 链级),从黄金样张反向提取
- **缺陷清单**: 单次质量评估的输出;每条含维度、位置、缺陷描述;是修复指令的直接原料
- **生命线账本**: 每篇内容的全程处理记录;校准统计与故障升级的数据源
- **校准语料**: 固定的端到端测试集(约 20 条,含 2 个负样本);管线配置变更的验收基准
- **黄金样张**: 当前质量标准的具象锚点(正样本全套文件);样张换代经提案程序
- **修复适配卡**: 本循环向通用修复框架注册的身份证;含故障签名表、诊断线索、分级动作边界、验证与回滚方法;格式遵循全循环统一适配卡规范
- **故障账本**: 全部 fail-closed 事件的统一签名记录;升级规则与未来自动修复的数据源

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 校准语料端到端运行,≥90% 正样本在限定修复轮次内无人工介入走完全链入库
- **SC-002**: 负样本 100% 被拒于准入环节,且拒收发生在任何提炼资源消耗之前
- **SC-003**: 黄金样张原文 URL 端到端重跑,产出通过 14 步清单全部标准(结构等价)
- **SC-004**: 从 URL 入队到入库/拒收的全过程,人工介入次数为 0(红线变更与故障升级除外)
- **SC-005**: 任意一篇已处理内容,其各环节判定、修复轮次、资源消耗可在账本中完整回查
- **SC-006**: 抽检达标率跌破阈值后,校准任务在下一个心跳周期内自动创建,无需人工发现
- **SC-007**: 单篇处理的修复轮次与资源消耗不超过声明上限;超限内容 100% 留在候选区且原因可读
- **SC-008**: 知识库主人的常态时间投入降至每周读一份摘要(≤10 分钟),质量反馈类对话次数为 0

## Assumptions

- 部署目标为 Mac mini(24 小时在线);**常驻连续运行**,串行单工 + 源轮询限频作为资源天花板,与现役三条链路共存无需错峰;部署遵循 `docs/mac-mini-deployment-notes.md` 既有约定
- 抽检触发阈值初始值:周抽检样本(3 篇)量规达标率 <80% 触发校准;校准期数据回流后可调(参数级变更,默许制)
- 准入三判定的初始判定题从黄金样张与两个负样本的对照中提取;首月校准期内允许调整
- 修复循环上限沿用既有收敛模式(3 轮);校准循环每次配置变更后全量重验,变更尝试同样有界
- "知识库内容标准修订"(取消逐条人批 → 五道门自动升格)由知识库主人在知识库侧按其修订程序执行;本 feature 在修订生效前以提议模式运行,生效后切换为自动升格,切换本身不需要代码变更以外的迁移
- 双轨试运行期长度:前 50 条自动入库内容;期满且无误放回滚记录后,快照保留策略可放宽(参数级变更)
- 校准语料初始 20 条由知识库主人认可的领域配比构成,正样本以黄金样张为上限基准、不要求每条都达样张级(语料代表真实输入分布,含应拒收项)
