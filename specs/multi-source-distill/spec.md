# Feature Spec: 多源提炼 + 概念图谱锚定(循环1 入库率/质量平衡)

**Created**: 2026-06-28
**Status**: Draft(设计已与用户对齐,待 P0 地基完成后实施)
**关系**: 循环1 目标架构 v2。前置依赖 P0(加权分=0 修复等,见 [[project_akb2_loop1_bottleneck_priority_2026-06-28]])。

## 背景与目标(WHY)

现状循环1 是 **1 篇抓取 → 1 篇提炼**:一篇薄源单独成不了一页 wiki 就失败、源被浪费。满仓 0/18 里有一批正是"源真薄、单篇凑不齐概念机制(F4 要 ≥3 命名组件+因果边)"。

目标:**raw 不够独立成页时不丢,挂到概念图谱上攒料,够了再合成一页 wiki**——保入库率、不浪费源、且不降质量。agent 只读 wiki 层,raw 层标准要"清晰但不严"。

## 范围(SCOPE)

**v1 只做 create(本 spec)**:概念还没 wiki 页 → 攒够 raw → 第一次合成出新页。
**v2 再做 update**(不在本 spec):新 raw 并入已有 wiki 页(需 merge + 重评分 + 版本管理,改线上内容,谨慎)。
**升星(独立未来,不在此)**:wiki→wiki 无新料的二度/三度/四度深化,持续推高 How 密度/可执行性。与多源提炼正交(多源=新 raw 料汇入;升星=不引新料自我深化)。

## 已锁定的设计决策

1. **准入用 deepseek**,砍掉 gemini-flash。准入判源(不是判提炼产物)→ 不破 Maker/Checker 异族(maker=deepseek 提炼/准入,checker=gpt-5.4 守卫)。回到两模型。
2. **raw 门与 wiki 标准对齐:同一套标准,差别是"完成度"不是"严格度"**(不另立松标准/拍脑袋阈值旋钮):
   - 同一 taxonomy + 同一"什么算机制/知识"定义。raw 门判:这篇对 wiki 标准里的**某个概念**,是否提供 **≥1 个合格知识贡献**(命名机制组件 / 可溯源论断),用 wiki 同一套定义判(deepseek 轻判)。
   - 有 ≥1 有效贡献 → 收进 raw 等攒(哪怕单篇凑不齐 wiki 要的 ≥3 组件+因果边);对**任何**概念零贡献(新闻/营销/纯观点/噪音)→ 拒(**与 wiki 负样本同口径**)。
   - 纯机判前置(先挡不可用):抽取成功 + 去重(content_hash) + 非噪音/导航/付费墙(抽取层已做)。
   - **区别一句话**:wiki 要"这一页**自身**达标(≥3组件+因果边过门)";raw 要"这是**同一标准下的有效部分**(哪怕 1 个组件)"。raw = wiki 标准的"部分/未完成态",不是低标准。
   - 移出 raw 门(成页时才判):how 密度阈值 / 车道分类 / 新颖度。但"是不是知识、属哪个领域概念"用 wiki 同一把尺,不另设。
   - 好处:不收 wiki 永远不要的垃圾;两层不打架;砍掉独立阈值旋钮。同时简化了现在那套 4 判定准入。
3. **概念图谱锚定路由,不用 embedding 相似度聚类**(相似≠同一概念,聚类会把"相邻但不同"混成一锅):
   - 复用现成基建:已有概念节点(`known_concepts`=wiki/concepts+wiki/sources)+ pending 槽(`pending_queue`,staging concept-backlinks)+ 图谱边。
   - 提不出页的 raw → deepseek 判它"讲的是图谱里哪个概念" → 挂到对应 **pending 槽**(v1 只挂 pending,命中已有节点的并入=update 属 v2)。
   - 相关性来自图谱拓扑(讲这个概念),不来自向量距离。
4. **触发提炼**:某 pending 概念槽来自 **≥K 个不同源** 的料够了(或单篇够厚走 1:1 快路径)→ 只对**这一个概念**合成提炼出一页。超时没攒够 → 标"源不足"告警,不无限囤。
5. **多源合成(deepseek maker)**:收 N 个 raw 的抽取片段(机制点/claims,非全文硬拼),合成一页:命名机制组件跨源凑齐、因果边跨源建立、**每条论断标注来自哪个源**(多源 provenance,`[raw §X@source-k]`)。这正解"单源凑不齐 ≥3 机制组件"的 F4 卡点。
6. **不混不相干内容(双保险)**:
   - 输入侧 scoped:提炼某概念页只喂"挂在这个概念上的料",源头过滤;**只 scoped 到该节点,不卷图谱邻居**。
   - 输出侧 F4 兜底:F4 要"≥3 命名机制组件 + 因果边连通"——混了不相干内容则因果边连不起来 → F4 自动拒(现有地板=天然连贯性守门)。
7. **单篇够厚走 1:1 快路径**:raw 入池做轻量厚度预判(确定性:抽出机制组件候选 ≥3 即厚),够厚立即 1:1 提炼,不必等攒。厚源快、薄源攒。
8. **embedding 降级为辅助**:不做最终归组,只做"新概念提名去重"的召回(找近义候选,deepseek 判是否同一概念),防概念碎片化。

## 数据流(v1)

```
抓取 →[raw 门:抽取成功+非噪音+去重+领域相关(deepseek),清晰不严]→ raw 暂存
  ├─ 单篇够厚(机制组件候选≥3) → 1:1 提炼 ──────────────┐
  └─ 不够 → deepseek 判讲哪个概念 → 挂 pending 概念槽      │
              某槽 ≥K 个不同源料够 → 只对该概念 N:1 合成 ──┼→[质量门:F4连贯+grader+加权≥6.0]→ wiki(新页/create)
              超时没攒够 → 标"源不足"告警                  ↑ 不过不丢→退回槽等更多源
```

## Functional Requirements

- FR-1 raw 门 MUST 与 wiki 用同一套标准(taxonomy + 知识/机制定义),差别仅为完成度:MUST 收"对某概念 ≥1 合格知识贡献"的源、MUST 拒"对任何概念零贡献"的源(与 wiki 负样本同口径);MUST NOT 另立独立的松阈值标准。纯机判前置(抽取成功/去重/非噪音)先挡不可用。
- FR-2 准入领域相关判定 MUST 用 deepseek(不用 gemini-flash);不参与给提炼产物打分,不破异族。
- FR-3 提不出页的 raw MUST 不丢弃,MUST 由 deepseek 路由挂到一个具体概念(v1:pending 槽)。
- FR-4 路由 MUST 锚定到离散概念身份(图谱节点/槽),MUST NOT 用 embedding 相似度做最终归组(embedding 仅用于新概念去重召回)。
- FR-5 N:1 合成 MUST 只喂挂在该概念上的料,MUST NOT 卷入图谱邻居;每条论断 MUST 多源可溯源。
- FR-6 合成页 MUST 过现有质量门(F4 连贯 + grader + 加权过阈),不放宽地板。
- FR-7 单篇够厚 MUST 可走 1:1 快路径,不必等攒。
- FR-8 v1 MUST NOT 触碰/改写已入库 wiki 页(update 属 v2)。

## 不做(明确排除)

- update(并入已有页 + 重评分 + 版本)→ v2。
- 升星(wiki→wiki 深化)→ 独立未来。
- embedding 做最终归组聚类(只做去重召回)。

## 前置依赖与风险

- **强依赖 P0**:N:1 合成出来照样过同一 grader/加权门。加权分=0 不修(P0:grader 必填逐维 score + 尺度钉 0~1 + 阈值 6.0),合成多好也是 0 分。**P0 必须先于本 feature**。
- **新增有状态**:循环1 从"逐篇无状态"变"有状态的 pending 概念槽 + 路由 + 触发调度";要定槽存储位置、触发时机、与每日 briefing 自动化的衔接。
- **eval harness 要改**:现满仓是"1 URL→1 页"假设;N:1 改变"通过"定义,校准框架需配套改。
- **新概念去重**:提名新概念要保守 + 去重,防同一概念开成多个槽(碎片化)。

## 验收(Success Criteria)

- SC-1 一篇单独 1:1 会失败的薄源,挂到概念槽、与 ≥K 个同概念源合成后,能出一页过质量门(F4+grader+加权)的 wiki。
- SC-2 不相干源被合进同一页时,因 F4 因果边不连通被拒(连贯性守门生效)。
- SC-3 raw 门只挡不可用,不误杀"暂时单薄但领域相关"的源(它们进池等攒)。
- SC-4 单篇够厚仍走 1:1 快路径,时效不退化。
- SC-5 v1 全程不改写任何已入库 wiki 页。
