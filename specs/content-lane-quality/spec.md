# Feature Specification: 循环1 内容类型分流质量标准

**Created**: 2026-06-26
**Status**: Draft
**Input**: 用户描述（由 2026-06-25/26 设计会话推导，命令输入为空）："循环1 的提炼标准太单一——把 How 密度/可执行性放在首位，系统性误杀了有价值的概念型内容。要让循环1 从事实上的『命令清单库』变成能同时收录概念型与操作型知识的『概念图谱知识库』。"

## 背景与目标 *(WHY)*

循环1 是知识库唯一的入库出口。现状把"是否含足量可执行命令"（How 密度/可执行性）当作核心质量门，导致**纯概念型内容（讲清机制但无命令，如架构模型、设计原则）被系统性拒收**——满仓校准中概念源 0% 通过。这违背"概念图谱知识库"的本意，使知识库退化为命令清单库。

本 feature 让质量标准**按内容类型分流**：概念型内容按"机制讲得清不清楚"评判、操作型内容仍按"可执行性"评判；同时用一组不可妥协的**完整性底线**守住可信度，防止放宽标准后让低质内容漏入。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 概念型内容能入库 (Priority: P1)
一篇高价值的概念型内容（清晰阐述某机制/架构，但不含可执行命令）提交后，能走完循环1 全链、达到质量标准并入库，而不会因"没有命令"被拒。

**Why this priority**: 这是本 feature 的核心目的——现状此类内容通过率为 0，知识库因此漏掉大量有价值的概念知识。

**Independent Test**: 取一篇纯概念型内容（0 可执行命令、但机制阐述清晰，如 LangChain《The Art of Loop Engineering》四层 loop 模型），跑完循环1，验证其达标并进入候选/入库，而非被拒。

**Acceptance Scenarios**:
1. **Given** 一篇机制阐述清晰、无可执行命令的概念型内容, **When** 走完循环1 全链, **Then** 它被判为概念型车道、按机制清晰度等概念标准评判、并达标入库。
2. **Given** 同一篇内容, **When** 评判, **Then** 系统不因"缺少可执行命令"对它扣分或拒收。

### User Story 2 - 操作型内容标准不放松 (Priority: P1)
一篇命令型 how-to 内容仍按原有严谨标准（含足量可执行步骤）评判，新模型不因引入概念车道而放松对操作型内容的要求。

**Why this priority**: 分流不能以牺牲既有质量为代价；操作型内容是已验证的优势区，不可回归。

**Independent Test**: 用既有操作型黄金样张重跑，验证其仍达标、且判定口径未放松（不会因新模型出现质量松动）。

**Acceptance Scenarios**:
1. **Given** 既有操作型黄金样张, **When** 在新模型下重跑, **Then** 仍达标入库，结果与旧标准等价（无回归）。
2. **Given** 一篇声称操作型但缺少任何可执行步骤的内容, **When** 评判, **Then** 它在操作型车道因核心价值不达标被拒。

### User Story 3 - 低质内容被正确拒 (Priority: P1)
放宽对概念内容的要求后，低质内容（机制讲不清的清单、无依据引申的读后感、洗稿、零增量重复）仍被正确拒收，不漏入知识库。

**Why this priority**: 知识库污染代价高且难回滚；"能收概念内容"绝不能演变成"什么都能进"。

**Independent Test**: 用三类低质负样本（机制糊清单水文 / 无据飘浮读后感 / 洗稿）跑循环1，验证 100% 被拒，并能指出被哪道判定拦下。

**Acceptance Scenarios**:
1. **Given** 一篇只罗列概念名词、组件间无因果关系的清单内容, **When** 评判, **Then** 因核心价值（机制清晰度）不达标被拒。
2. **Given** 一篇大量引申且引申无法溯源到来源事实的读后感, **When** 评判, **Then** 因完整性底线（解读有据）不达标被拒。
3. **Given** 一篇与既有内容高度重叠的洗稿, **When** 评判, **Then** 被拒（沿用既有准入判定）。

### Edge Cases
- **混合内容**（机制阐述 + 示例代码/命令）→ 按**主导意图**判：示例服务于机制解释则归概念型；主价值是目标完整的可复现操作流程才归操作型。
- **非知识内容**（新闻播报/产品发布/营销/纯观点）→ 准入 reject 拒收，不进入车道（不靠 how_tendency 豁免漏过）。
- **概念内容机制踩线但堆辅助维度**：机制刚好达底线、却靠次要维度把质量分凑高 → 必须仍被拒（核心价值不足，不能靠辅助维度补偿）。
- **概念内容解读占比高但有据**：大量引申但每条都能溯源到来源事实 → 应通过（解读多不是问题，无据才是）。
- **来源本身达不到标准**（如操作型源天然无任何命令）→ 当前直接拒并记账（自动换源属未来的源汰换循环，不在本 feature 范围）。

## Requirements *(mandatory)*

### Functional Requirements
- **FR-001**: 系统 MUST 在准入阶段将每篇内容判定为「概念型」或「操作型」车道之一，并将该车道贯穿后续提炼、校验、评分、修复全程。
- **FR-002**: 车道判定 MUST 按内容**主导意图**，而非代码/命令出现与否。仅当主价值是引导读者完成可复现操作（含目标完整的步骤序列/命令/配置）时判「操作型」；示例代码、API 名、编号机制点不单独决定车道。新闻播报/产品发布/营销/纯观点等既不阐述可复用机制、也不教可执行操作的**非知识内容 MUST 在准入被拒（reject）**，不得为二选一硬塞「概念型」而靠 how_tendency 豁免漏过。
- **FR-003**: 概念型内容 MUST NOT 因缺少可执行命令而被扣分或拒收。
- **FR-004**: 系统 MUST 按内容车道选用对应质量画像评判——概念型以"机制阐述清晰度"为核心价值，操作型以"可执行性"为核心价值。
- **FR-005**: 入库判定 MUST 包含一组「完整性底线」（论断可溯源、证据诚实、解读有据、车道核心价值达标）；任一底线不达即拒，且这些底线 MUST NOT 被其他维度的高分补偿。
- **FR-006**: 完整性底线之上的质量维度 MUST 被合成为单一的"通过/不通过"阈值判定；该合成分数 MUST NOT 被用于候选之间的排序择优。
- **FR-007**: 系统 MUST 拒收低质内容，至少覆盖：机制讲不清的罗列式内容、引申无法溯源的读后感、洗稿、零增量重复。
- **FR-008**: 质量评判 MUST 同时产出可定位的缺陷清单（供定点修复使用），MUST NOT 仅输出一个无定位的总分。
- **FR-009**: 概念型内容的"解读"成分 MUST 按"是否可溯源到来源事实"评判，而非按其占全文比例评判。
- **FR-010**: 质量标准的具体权重与阈值 MUST 与判定逻辑分离（存于可版本化的标准定义处），使其调整无需改动判定代码。

### Key Entities
- **内容车道 (Content Lane)**: 概念型 / 操作型二选一；决定该内容用哪套质量画像与核心价值维度。
- **完整性底线 (Integrity Floor)**: 一组不可交易、不可被补偿的硬判定（可溯源 / 诚实 / 有据 / 车道核心价值）；任一不达即拒。
- **质量画像 (Quality Profile)**: 某车道下各质量维度的相对重要性配置 + 通过阈值；是上条 FR-010 中"与代码分离"的对象。

## Success Criteria *(mandatory)*

### Measurable Outcomes
- **SC-001**: 至少一篇纯概念型内容（0 可执行命令、机制阐述清晰）能走完循环1 全链并达标入库（现状此类通过率 = 0%）。
- **SC-002**: 既有操作型黄金样张在新模型下重跑仍达标，判定结果与旧标准等价（操作型 0 回归）。
- **SC-003**: 三类低质负样本（机制糊清单 / 无据读后感 / 洗稿）在评判中 100% 被拒，且每个能定位到拦截它的判定项。
- **SC-004**: 不存在"靠堆高次要维度分把核心价值不足的内容顶过阈值"的漏放——对抗性构造的假阳性样本被拒。
- **SC-005**: 调整任一车道的权重或阈值无需修改判定逻辑代码（仅改标准定义即可生效），且改动后判定行为随之变化可被验证。

## Assumptions
- 标准沿用既有黄金样张（`addy-osmani-loop-engineering`）锚定，**不另立概念型黄金样张**（用户 2026-06-26 决定）；首篇通过的概念页将作为后续概念内容修复时的爬坡标杆。
- 宪法 v1.2.0 已认可"完整性底线（硬 pass/fail）+ 地板之上加权质量分（过阈、不排序）"模型（原则 6/8 已于 2026-06-26 修订），本 feature 是该原则的落地。
- 权重数值与阈值属校准产物，不在本 spec 固定（落在版本化标准定义中，见 FR-010）。
- 本 feature **不含**"内容抓取层修复"——SC-001 的验证可用概念内容的原文/fixture 直接喂入判定阶段，绕开实时抓取；实时抓取的源失效问题属独立工作项（另一份计划），不在本 feature 范围。
- 混合内容归操作型车道是有意的从严选择（避免低估，宁可按更严的操作标准判）。
