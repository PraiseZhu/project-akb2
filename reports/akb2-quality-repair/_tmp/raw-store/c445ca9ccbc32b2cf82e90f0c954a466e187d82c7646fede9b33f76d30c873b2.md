# AI SDK Agent Harness — Tool Use, Streaming, and Multi-Step Patterns

§B_INTRODUCTION

## Overview

The Vercel AI SDK provides a harness for building agent-based applications with
built-in support for tool use, streaming responses, and multi-step reasoning
loops. This document covers the three core patterns that make up the agent
harness: tool registration and invocation, streaming intermediate results, and
the multi-step loop that ties them together.

§C_CONTEXT

## Tool Use Pattern

§D_ARGUMENT

### Tool Registration

Tools are registered as typed definitions with a name, description, input
schema, and an execute function:

§E_CLAIMS

```typescript
import { tool } from 'ai';
import { z } from 'zod';

const searchTool = tool({
  description: 'Search the web for current information',
  parameters: z.object({
    query: z.string().describe('The search query'),
    maxResults: z.number().default(5),
  }),
  execute: async ({ query, maxResults }) => {
    const results = await searchWeb(query, maxResults);
    return results;
  },
});
```

§F_EVIDENCE

The schema serves dual purpose: it validates inputs at runtime and provides
the model with a structured description of what the tool expects. The model
uses the description and parameter names to decide when and how to call the
tool.

§G_EXAMPLES

### Tool Invocation Flow

When the model decides to call a tool, the harness:

§H_HOW_STEPS

1. Extracts the tool name and arguments from the model's response
2. Validates arguments against the registered schema
3. Calls the execute function
4. Feeds the result back to the model as a tool response
5. The model then decides whether to call another tool or produce a final answer

This loop continues until the model produces a response without a tool call,
or a maximum step count is reached.

§I_LIMITATIONS

### Error Handling

§J_DISCUSSION

Tool execution errors are caught by the harness and fed back to the model as
error messages. The model can then decide to retry with different arguments,
try a different tool, or report the failure to the user. This gives the model
agency in error recovery rather than failing the entire conversation.

## Streaming Pattern

§K_IMPLICATIONS

### Token-Level Streaming

The harness streams model output token-by-token via a readable stream. This
allows the UI to render partial responses before the model finishes generating:

§L_RELATED_WORK

```typescript
import { streamText } from 'ai';

§M_PARAMS

const result = streamText({
  model: myModel,
  messages: conversationHistory,
});

for await (const delta of result.textStream) {
  console.write(delta);
}
```

§N_DATA

### Multi-Step Streaming with Tool Calls

§O_METHODOLOGY

In a multi-step loop, the harness streams both text deltas and tool call
events. The consumer can distinguish between:

- `text-delta`: partial text from the model
- `tool-call`: the model is requesting a tool invocation
- `tool-result`: the tool has returned a result
- `finish`: the model has produced a final response

§P_RESULTS

This allows the UI to show real-time progress: "Searching the web...",
"Reading results...", "Generating answer..." while the agent works.

## Multi-Step Loop

§Q_ANALYSIS

### Loop Structure

§R_RECOMMENDATIONS

The multi-step loop is the core of the agent harness. It alternates between
model reasoning and tool execution:

```
1. Send conversation history + tool definitions to model
2. Receive model response (text + optional tool calls)
3. If tool calls present:
   a. Execute each tool call
   b. Append tool results to conversation history
   c. Go to step 1
4. If no tool calls: return final response
5. If step count exceeds maxSteps: return with a "max steps reached" marker
```

§S_CODE

### maxSteps Budget

The `maxSteps` parameter caps the number of model calls in a single
conversation turn. This is a hard budget — the loop terminates regardless of
whether the model has finished. Typical values range from 5 (simple Q&A with
one or two tool calls) to 50 (complex research tasks with many tool calls).

§T_CONFIGURATION

### Convergence Detection

§U_BENCHMARKS

The loop converges when the model produces a response without any tool calls.
This is the signal that the model has gathered enough information and is ready
to produce a final answer. The harness does not attempt to detect convergence
early — it trusts the model to stop calling tools when it's done.

### Conversation History Management

§V_OBSERVATIONS

Each step's model response and tool results are appended to the conversation
history. For long-running agents, this history can grow large. The harness
provides hooks for context window management:

- Truncation: keep only the last N messages
- Summarization: replace older messages with a summary
- Selective retention: keep tool results but drop intermediate text

§W_CAVEATS

These hooks are optional — the default behavior is to keep the full history
and let the model's context window limit naturally cap the conversation.

§X_ALTERNATIVES

## Integration with UI

The harness is designed to integrate with React Server Components and
streaming APIs:

§Y_REFERENCES

```typescript
// app/chat/route.ts
import { streamText } from 'ai';

export async function POST(req: Request) {
  const { messages } = await req.json();
  const result = streamText({
    model: myModel,
    messages,
    tools: { search: searchTool, calculator: calcTool },
    maxSteps: 10,
  });
  return result.toDataStreamResponse();
}
```

§Z_CONTENT_END

The `toDataStreamResponse()` method serializes the stream into a format that
the `useChat` hook on the client can consume, providing real-time UI updates
as the agent works through its tool calls and reasoning steps.
